## Context

目前 UI 目錄搜尋僅嘗試 `tui/` 與 `../tui/`，當 CLI 從 `core/` 目錄執行時會找不到 UI 目錄而失敗。需要在不改變主要架構的前提下，讓 CLI 能在常見開發工作目錄下正確定位 UI。

## Goals / Non-Goals

**Goals:**
- 定義清楚且可預期的 UI 目錄搜尋順序。
- 在 `core/` 或專案根目錄啟動時都能找到 `tui/`。
- UI 目錄不存在時提供可診斷的錯誤訊息。

**Non-Goals:**
- 不新增外部依賴或改變 UI 啟動方式。
- 不處理使用者自訂 UI 目錄的設定檔功能。

## Decisions

- **搜尋策略**：採用固定清單的相對路徑搜尋，依序嘗試 `tui/`、`../tui/`、`../../tui/`，覆蓋專案根與 `core/` 目錄啟動情境。此策略簡單可預期，避免引入專案根偵測的複雜度。
- **錯誤輸出**：當所有路徑失敗時，輸出目前工作目錄與已嘗試路徑清單，提升診斷效率。
- **行為一致性**：保留現有成功時的 `cwd` 設定與 child process 啟動方式，僅擴充搜尋與錯誤訊息。

## Risks / Trade-offs

- **[Risk]** 搜尋路徑固定且有限，若專案結構改變可能失敗 → **Mitigation** 保持路徑清單集中在單一區塊，日後易於調整。
- **[Trade-off]** 沒有動態偵測 repo root → **Mitigation** 以覆蓋常見開發目錄為主，避免引入額外依賴與不確定性。
