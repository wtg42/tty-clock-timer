## Context

目前 core 模組（config/timer/ipc/main）的測試覆蓋率不足，錯誤路徑與邊界行為缺少驗證。此變更聚焦於補齊測試與盤點缺口，不改變對外行為。

## Goals / Non-Goals

**Goals:**
- 系統性盤點 core 的功能缺口與風險場景。
- 補齊單元測試涵蓋錯誤路徑、邊界輸入與狀態轉換。
- 以最小行為改動提升可回歸驗證能力。

**Non-Goals:**
- 不新增新功能或改變 CLI/IPC 協議的對外行為。
- 不進行大規模重構或架構改寫。

## Decisions

- 先建立缺口清單再補測試，避免漏掉核心路徑。
  - 替代方案：直接補測試；風險是缺口盤點不完整。
- 優先補齊錯誤與邊界情境，再擴增一般流程測試。
  - 替代方案：平均分配；可能導致關鍵錯誤路徑仍無覆蓋。
- 只在需要提升可測性時進行最小重構（例如抽出可測函式）。
  - 替代方案：維持現狀；會限制測試範圍。

## Risks / Trade-offs

- [測試與行為不一致] → 新增測試前先確認現行行為，必要時以最小變更修正明顯錯誤。
- [覆蓋率提升成本] → 以高風險區域優先，避免全面性重寫測試。

## Migration Plan

不需部署或資料遷移，僅新增/調整測試與少量可測性輔助函式。
